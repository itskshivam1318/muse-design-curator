# Put Into Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Connect one picture to another with a line, aim at a spot (a part and every part of the same kind, or a point), optionally add words, and get a new picture of the target with the source put in.

**Architecture:** Backend: a `put_into` job pastes the source's subject into each spot's box on a copy of the target, asks the existing single-image edit provider to blend it in, and composites the edit back inside the union of the spots only; the result is a new item (parent = target, `put_source_item_id` = source). Frontend: a new `src/put/` module owns the connect dot, the drag line, aiming, the card and the client-only ghost; the card and ghosts are living-board bodies so nothing overlaps.

**Tech Stack:** FastAPI, SQLAlchemy, Alembic, Pillow/numpy (backend); React, TanStack Query, Konva + the living-board physics (frontend); pytest, vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-03-put-into-design.md`

## Global Constraints

- Connect only: dragging a picture still only moves it; no drop-onto behaviour.
- Images only, as both source and target; a staged (unkept) take cannot be either; source ≠ target.
- One source per result. The target and the source are never modified.
- Copy (exact): card input placeholder `Anything to add? (optional)`, max 200 characters; buttons `Cancel` and `Put in`; chips `✓ <part label>` / `✓ Here`; ghost overlay `Putting in…`; error tile buttons `Retry` and `Dismiss`; card title `<source title> → <target title>` using `itemTitle` (`src/format.ts`), falling back to `Picture`.
- A point spot's box is a square of side `0.2 × min(target width, target height)` (pixels), centred on the point and clamped inside the image.
- Counts one slot of the board's daily `render` limit; refunded on **any** failure, model failures included.
- Refused while demo-locked (the existing demo middleware already blocks the new POST; the dot is hidden when `readOnly`).
- Nothing on the board may overlap: the card is an `obstacle` body, each ghost an `item` body.
- Accent `#2b44c4` for the dot, line and spot highlights (the board's existing accent).

## Review Focus

1. Target has no analysis yet (pending) or it failed → aiming still works with a single point spot ("✓ Here"). Test in Task 5.
2. A point near the image edge → the point box is clamped fully inside the image, never off it. Test in Task 2.
3. Source or target removed (or staged) while the job runs → the job fails with `put.failed`, the slot is refunded, nothing is created. Test in Task 3.
4. Double-clicking Put in → exactly one request; the button is disabled while it is in flight. Test in Task 7.
5. Line released over the source itself, a note, a link, a video or empty board → nothing is created and the line disappears. Test in Task 6.

- Produces:
  - `POST /api/items/{target_id}/put-into`, body `PutIntoBody { source_id: str; spots: list[{"part": str} | {"point": {"fx": float, "fy": float}}] (1..8); words: str | None (≤ 200) }` → **202** `{"job_id": str, "x": float, "y": float, "w": float, "h": float}` (where the result will land).
  - Errors: 404 `ITEM_NOT_FOUND`; 422 `PUT_NOT_IMAGE` (either side not an image, staged, or source == target); 422 `PART_NOT_FOUND` (a spot names no live part of the target); 429 `DAILY_LIMIT`.

  - `subject_of(session, source) -> tuple[Image.Image, str]`: the source as is when it `has_alpha`; else, if its analysis has exactly one image part or a part whose box covers ≥ 60% of it, that part cut out by its mask (locating it if needed); else the whole picture. The name is `itemTitle`-equivalent: `page_title` or `original_filename` stem, else `"the reference"`.
