# Build on one key, open corpora, Python

**Build against one interface: the OpenAI-compatible Meta Model API at `https://api.meta.ai/v1`, using a single Bearer key for both `muse-spark-1.3` (vision-language reasoning) and `sam-3.1` (segmentation).** India is cleared for both. Muse Image is the only model blocked there, which fits a design that retrieves images instead of generating them. Meta offers no embeddings endpoint, so the embedder has to be your own. For the corpus, use **CC0 museum open-access sets (Met, Smithsonian/Cooper Hewitt, Art Institute of Chicago, Rijksmuseum) plus per-file-licensed Wikimedia Commons**, with a small, attributed, API-fetched slice of Pexels for contemporary scenes. Exclude Unsplash and the V&A: their terms require hotlinking, restrict AI use or cap caching. No licensed source covers UI screens. Modern wristwatches are covered only thinly, by Commons. You have to build both of those corpora deliberately rather than download them. The stack is a **Python FastAPI backend, SigLIP 2-B (or Meta's PE-Core-B16) as the embedder, NumPy brute-force cosine plus SQLite, a React + react-konva front end on Vercel, and the backend on a Hugging Face Space or Modal**. Retrieval follows the published training-free composed-retrieval recipe: VLM attribute JSON, then filter, then fused cosine, then a VLM rerank. Two hard dates matter. **The $150 credit claim form and the project submission both close at Nov 4, 9:00 PM ET, which is 07:30 IST on Nov 5.** Today is Oct 26, so you have about nine and a half working days. The claim is applied within about two business days, so file it in the first days, not at the end.

## One key covers Muse Spark 1.3 and SAM 3.1, but nothing embeds

Meta ships no client library for its text models. You use the stock `openai` package (pip or npm) and pass both the base URL and the key explicitly, because "The OpenAI SDK doesn't auto-read `MODEL_API_KEY`" ([Quickstart](https://dev.meta.ai/docs/quickstart)). Keys start with `LLM_`, are shown once, belong to a team, and share that team's rate limits. Meta tells you to proxy all calls through your own server ([Authentication](https://dev.meta.ai/docs/authentication)). The API also accepts Chat Completions and the Anthropic Messages format. **The Responses API (`POST /v1/responses`) is the recommended surface.** It is the only one that carries chain of thought between calls and the only one with search grounding ([Responses API](https://dev.meta.ai/docs/protocols/responses)). A Responses reply returns an `output[]` array: a `reasoning` item, then a `message` item whose `content[].type == "output_text"` holds the answer. `usage.output_tokens_details.reasoning_tokens` is billed as output ([Quickstart](https://dev.meta.ai/docs/quickstart)).

**Muse Spark 1.3** has a **1,048,576-token context** and takes text, image, MP4 video, audio and PDF input ([Models](https://dev.meta.ai/docs/models)). The documented OpenCode configuration sets a 131,072-token output limit ([Quickstart](https://dev.meta.ai/docs/quickstart)). Images can arrive as a public URL, a base64 data URL or a Files API `file_id`. A request can carry **at most 50 images; a 51st returns HTTP 400**. Inline images are capped at 50 MB, Files API uploads at 1 GiB, and the accepted formats are JPEG, PNG, GIF, WebP and ICO. **A ~1280px image costs about 1,300–1,500 input tokens.** Grounded boxes come back on a 0–1000 normalised grid, which you should clamp ([Image understanding](https://dev.meta.ai/docs/image-understanding)). Structured output is real and constrained. Pass `text.format` on Responses or `response_format: {type: "json_schema", ...}` on Chat Completions. Output conforms to the schema even with `strict: false`. Recursive schemas are rejected, and nesting is limited to 10 levels ([Structured output](https://dev.meta.ai/docs/structured-output)). **`tool_choice` accepts only `"auto"`**, so use structured output, not forced tool calls, whenever you need guaranteed JSON ([Tool calling](https://dev.meta.ai/docs/tool-calling)). Several Chat Completions parameters return 400, including `stop`, `n>1`, `logprobs` and `reasoning_effort: "none"`. Reasoning effort runs from `minimal` to `xhigh`, with `max` available on 1.3 Standard ([Chat completion](https://dev.meta.ai/docs/protocols/chat-completions)).

**SAM 3.1** uses the same `POST /v1/responses` endpoint with `model: "sam-3.1"`. The request carries one `input_text` and one `input_image` (or video). The text is either a short noun phrase such as "red hat" or box/point token prompts, never both. **Each request handles one concept, and it returns every matching instance.** Lists, "and" and spatial phrases do not work, so three concepts cost three parallel calls. Options go in `metadata` as strings: `include_confidence: "true"` and `mask_encoding: "one_bit"` (smaller) or `"lossless"` ([SAM segmenting](https://dev.meta.ai/docs/sam/segmenting)). **The output is special-token text, not JSON or RLE.** Each line has a `<0f>` frame marker followed by records like `id<|box;x1=..;y1=..;x2=..;y2=..;w=..;h=..|><|mask;x=0;y=0;data=H,W,!payload|>`. The mask payloads are base85, and zero matches return an empty `output_text` ([Reading segmentation output](https://dev.meta.ai/docs/sam/reading-segmentation)). Do not parse this by hand. **`pip install meta-sam-parser` (Python 3.10+, zero dependencies) decodes masks to a raster, COCO RLE or an SVG path.** `@meta-sam/parser` does the same in Node ([Client libraries](https://dev.meta.ai/docs/sam/client-libraries)).

**Embeddings do not exist on the Meta Model API.** The docs index lists Responses, Chat Completions, Messages, Files, Images, Voice and Models, with no embeddings page ([llms.txt](https://dev.meta.ai/llms.txt)). An unauthenticated probe of `/v1/embeddings` returned 401, which proves nothing. Spend one authenticated request on it to confirm the expected 404, then plan on a local embedder.

**Muse Spark Open** is a separate open-weight model: 816B total parameters, 42B active, 1M context, released Oct 15, 2026 under the Muse Model License. **The license requires you to display "Built with Muse Spark Open"**, and NVFP4 inference needs at least 700 GB of VRAM, so self-hosting is off the table ([HF model card](https://huggingface.co/meta-models/Muse-Spark-Open-816B-A42B)). Its default reasoning effort is `xhigh`, so set `low` or `medium` on any interactive call. On Baseten it is an OpenAI-compatible Chat Completions endpoint at `https://inference.baseten.co/v1` with a Bearer `BASETEN_API_KEY` and **model `meta-models/muse-spark-open`**, priced at the same $1.25/$4.25 per million tokens as hosted Spark ([Baseten library](https://www.baseten.co/library/muse-spark-open/)). The id `meta-models/muse-spark-open-1026` that appears in some hackathon material is not on Baseten's pages. Send a one-token test call to each id. Modal offers it as a per-token "Shared Endpoint" but publishes no URL, auth scheme or price, so read those from the Modal console ([Modal blog](https://modal.com/blog/meta-muse-spark-open-now-available-on-modal)). Neither host documents JSON-schema output or the image-part format, so validate every response and retry on failure. **The criteria for an open-weight bonus prize could not be verified.** The event page sits behind a login, and Meta's public hackathon page lists no such category ([dev.meta.ai hackathon](https://dev.meta.ai/events/global-hackathon)). Confirm on Discord before routing a core feature through Baseten.

### India access, credits and failure modes

An older July blog post described the preview as US-only ([Meta dev blog](https://dev.meta.ai/resources/blog/build-with-muse-spark/)). The current Geographic Use Policy supersedes it. **India is not a Restricted Territory, and the only India-specific block is on Muse Image** (Pakistan and mainland China/Hong Kong are fully restricted). The policy also bans circumventing geographic controls, so do not use a VPN ([Geographic Use Policy](https://dev.meta.ai/legal/geographic-use-policy)). Never call `/v1/images/*`. The hackathon credit is **USD 150**. Claiming it requires your Team ID and a payment method on file, and the credit is applied within two business days. **Usage beyond the credit is charged automatically to that card**, and the docs describe no hard spend cap ([Credit Terms PDF](https://scontent-lax3-2.xx.fbcdn.net/v/t39.8562-6/863382756_2547674092403265_4283663620107745955_n.pdf)). Plan for three operational problems. First, a third-party benchmark measured **~39 s time-to-first-token** ([computeprices.com](https://computeprices.com/models/muse-spark-1-3)), so stream or use `background: true` for query-time calls. Second, non-streaming requests can hit a 504 that Meta says not to blindly retry. Third, large inline base64 combined with the default `store: true` can return 413, which `store: false` or the Files API avoids ([Error handling](https://dev.meta.ai/docs/error-handling)).

At these prices, tagging one corpus image costs about $0.003 with Spark at low reasoning effort (my estimate: ~1.4K input tokens plus a few hundred output tokens), and one SAM mask costs $0.0025. A 5,000-image corpus therefore costs roughly **$25–30 to fully pre-process**, well inside $150. Do not use the cheap `-contributor` tier ($0.10/$0.20) for corpus work. It grants Meta "permission to use your content to train future Meta models" ([Pricing](https://dev.meta.ai/docs/pricing-rate-limits)), and you cannot grant that over third-party images, especially Pexels and Pixabay, whose terms single out machine-learning use.

## Museums and Commons give legal depth; stock sites give modern look with strings attached

The legally cleanest material is **CC0 museum open access**, flagged per object so you can filter it mechanically. Each source has its own flag and access route:

- **The Met** waives all rights under CC0 for "unrestricted commercial and noncommercial use" ([metmuseum/openaccess](https://github.com/metmuseum/openaccess)). It needs no key. **Check `isPublicDomain` on every object**, because `primaryImage` is empty when the flag is false. The old `/v1/search` endpoint was retired on Oct 1, 2026, and its replacement `/v1.1/search` ignores the public-domain filter ([Met API docs](https://metmuseum.github.io/)). Rapid loops trip Imperva bot protection, which a 0.4 s delay fixes.
- **Smithsonian Open Access**, which includes Cooper Hewitt (CHNDM), is CC0 with a per-media `usage.access == "CC0"` flag. It is available as line-delimited JSON on a public S3 bucket, so **you can ingest without touching the rate-limited API**. That API's DEMO_KEY died after about 22 calls ([Smithsonian/OpenAccess](https://github.com/Smithsonian/OpenAccess)).
- **The Art Institute of Chicago** exposes `is_public_domain`. **Rijksmuseum** data can be used commercially without permission and is mostly PD/CC0, with CC BY on the rest ([Rijksmuseum data policy](https://data.rijksmuseum.nl/policy/)).
- **The V&A must be excluded.** Its API is non-commercial only, content may not be cached for more than four weeks, and images must be hotlinked rather than copied ([V&A terms §9](https://www.vam.ac.uk/info/va-websites-terms-conditions/)).

None of the museum terms reviewed mention AI or ML, and CC0 waives every right, so embedding and segmenting these images is clean. Wikimedia Commons carries per-file licences, mostly CC BY and BY-SA. Its API returns `LicenseShortName`, `LicenseUrl`, `Artist` (as HTML, so sanitise it) and `AttributionRequired`, which is enough for an exact credit line ([Commons API sample](https://commons.wikimedia.org/w/api.php?action=query&titles=File:Detailed%20view%20of%20dial%20of%20chronograph%20watch.jpg&prop=imageinfo&iiprop=url|extmetadata|size&format=json)). Wikimedia's rate limits are new in 2026. **IP-only clients get 10 requests per minute, but a compliant descriptive User-Agent raises that to 200** ([Wikimedia rate limits](https://www.mediawiki.org/wiki/Wikimedia_APIs/Rate_limits)), and generic agents like `python-urllib` get blocked ([User-Agent policy](https://foundation.wikimedia.org/wiki/Policy:Wikimedia_Foundation_User-Agent_Policy)). Openverse returns a ready-made legal `attribution` string. However, it forbids scraping its catalogue ([Openverse ToS](https://docs.openverse.org/terms_of_service.html)), and anonymous queries appear capped at 240 results ([Openverse API](https://api.openverse.org/v1/images/?q=wristwatch%20dial&page_size=5)), so register and verify an email before relying on it.

The stock sites look the most modern but carry the most legal risk:

- **Unsplash** fails on three counts. It **mandates hotlinking** of `photo.urls` and a download-event ping ([Unsplash API Guidelines](https://help.unsplash.com/en/articles/2511245-unsplash-api-guidelines)). It routes "any machine learning and/or artificial intelligence purposes" to a separate data programme ([Unsplash API Terms](https://unsplash.com/api-terms)). And it caps new apps at 50 requests an hour until a manual production review ([Unsplash docs](https://unsplash.com/documentation)). Exclude the live API. The free 25,000-image Unsplash Lite dataset is explicitly offered for model work ([Unsplash Dataset](https://unsplash.com/data)), but its own licence was not checked. Read it before using it.
- **Pexels** issues keys instantly, allows 200 requests an hour, and requires a prominent Pexels link plus a photographer credit ([Pexels API docs](https://www.pexels.com/api/documentation/)). Its Oct 20, 2026 terms, however, forbid "Bulk, large-scale or systematic copying" and automated data collection "for machine learning purposes" without permission ([Pexels ToS](https://www.pexels.com/terms-of-service/)).
- **Pixabay** has the same two clauses ([Pixabay Terms](https://pixabay.com/service/terms/)), and it requires self-hosting with a 24-hour cache in place of permanent hotlinking ([Pixabay API docs](https://pixabay.com/api/docs/)).

The defensible reading is that embedding a few hundred images fetched through the official API, each displayed with credit, is "authorised" use. A corpus of thousands is "systematic". So **keep Pexels to a curated slice of a few hundred images and email Pexels for written permission now.** All three stock sites also ban building a "similar or competing service". Present the product as a design-language analyser, not as a stock-photo browser.

## Wristwatches and UI screens need a corpus you construct

Coverage, not licensing, decides each domain. **Modern wristwatches are almost absent from open access.** Met "watch" results are mostly pocket watches from before 1900. Rijksmuseum returned **0** hits for *polshorloge* (wristwatch), and Cooper Hewitt returned 0 for "wristwatch" (live queries in the research notes; [Met API](https://metmuseum.github.io/), [Rijksmuseum search](https://data.rijksmuseum.nl/docs/search)). **Wikimedia Commons is the best licensed watch source.** It has 361 "wristwatch dial" and 876 "chronograph watch" file hits, with accurate captions such as Seiko and Rolex Daytona dial close-ups ([Commons search](https://commons.wikimedia.org/w/api.php?action=query&list=search&srsearch=chronograph%20watch&srnamespace=6&format=json)). Openverse adds Flickr CC material in mixed BY, BY-SA and BY-NC licences. The watch corpus should therefore be **Commons-first (a few hundred to about 1,000 images, ND and NC excluded), Openverse BY/BY-SA second, a few hundred Pexels lifestyle shots third, and museum timepieces as a deliberate "heritage" layer**. Visible logos bring trademark and implied-endorsement risk ([Pexels License](https://www.pexels.com/license/)), so never present a result as brand-affiliated.

For fashion and interiors, the problem is era, not volume. **Met 20th-century evening wear sampled 0/20 public domain**, while historical textiles, lace and costume are abundant at Cooper Hewitt (about 12,000 CC0 costume and textile objects, extrapolated from a shard sample) and at AIC (709 public-domain dresses) ([Smithsonian S3 CHNDM](https://smithsonian-open-access.s3-us-west-2.amazonaws.com/metadata/edan/chndm/index.txt)). About 70% of Met chairs in the sample were public domain. Museum images are isolated studio objects on grey backgrounds, not room scenes, so **contemporary streetwear and lived-in interiors have to come from the Pexels slice and from Commons**: 808 streetwear hits and 57,477 living-room hits, the latter noisy with paintings.

**UI screens have no licensed source at all.** Commons "dashboard UI" hits are open-source admin-panel screenshots. Openverse "mobile app UI" returned phone photos. The V&A has 8 "user interface" objects under restrictive terms ([Openverse API](https://api.openverse.org/v1/images/?q=mobile%20app%20UI&page_size=10)). You have two honest options:

- **Capture your own screenshots of permissively licensed open-source applications.** Record each project's licence in the provenance table, since screenshots of GPL or MIT software are generally usable but trademarked logos still apply. This is my inference and needs a per-project licence check.
- **Redefine the fourth domain as graphic and print design**, which open access covers well: about 18,000 CC0 Cooper Hewitt prints and drawings, plus about 5,000 Rijksmuseum posters with images (licences to verify per object).

A domain-agnostic engine can show that it transfers by running on a small self-built UI set of 200–500 screenshots. It does not need a large one.

Whichever sources you use, store provenance per image: `source`, `source_id`, `landing_url`, `creator_name`, `license_code`, `license_url`, `attribution_text`, `fetched_at`. Render credits from that table on every result card. Ingest from the official bulk channels (Met CSV, Smithsonian S3, Rijksmuseum dumps) and the keyed APIs, never by crawling HTML. That satisfies both the "no scraping" clauses in Openverse, Pexels and Pixabay and the credit requirements of CC BY and BY-SA.

## Python backend, open embedder, no vector database

**Write the backend in Python with FastAPI.** The LLM calls are equally easy in either language, because the same `openai` SDK works in Python and TypeScript ([Meta docs](https://dev.meta.ai/docs/)). Everything around them is Python-native, though: `meta-sam-parser`, NumPy mask maths, scikit-image Lab conversion with ΔE2000 colour distance, scikit-learn k-means palettes, and open_clip/transformers embedders. Keep Next.js or Vite + React for the UI only. Write one thin `meta_client` wrapper that holds the key server-side and exposes `tag(image) -> attribute JSON` (Responses with `text.format`, reasoning `low`) and `segment(image, noun) -> masks` (SAM 3.1 plus the parser).

**Use SigLIP 2 base (`google/siglip2-base-patch16-256`, Apache-2.0) as the single global embedder.** On the January 2026 LookBench fine-grained fashion benchmark it reached **59.44 Recall@1, against 41.07 for DINOv2-L** ([LookBench](https://arxiv.org/pdf/2601.14706)). It also has the text tower you need for "describe what you want" queries. **Meta's PE-Core-B16-224 (Apache-2.0 per its model card) is the A/B alternative** and carries a stronger Meta story for judges ([PE-Core-B16-224](https://huggingface.co/facebook/PE-Core-B16-224/commit/f1ebc681f0cd27604bb96b2d8f48dbc72ae7b05d)). No head-to-head benchmark was found, so time and spot-check both on 100 of your own images on day one and keep the winner. Skip the alternatives:

- **DINOv3** has a custom licence that requires "Built with DINOv3", and it has no native text tower ([DINOv3 License](https://ai.meta.com/resources/models-and-libraries/dinov3-license)).
- **Marqo-FashionSigLIP** would degrade on watches and UI.

Embeddings entangle colour with identity, so **compute colour deterministically instead**: take the SAM mask, then the masked pixels, then Lab k-means (k=5) palettes compared with ΔE2000. To embed a region, crop to the mask's box and paint the background neutral grey.

**Retrieval needs no vector database.** At 20,000 images, a 768-dimension float32 matrix is about 61 MB, and exact cosine is a single NumPy matmul taking milliseconds. Store it as `embeddings.npy` with a SQLite table for attributes and provenance. If you want SQL `where` pre-filtering without writing pandas, LanceDB does it as an embedded directory ([LanceDB filtering](https://docs.lancedb.com/search/filtering)). sqlite-vec is still pre-v1 with "breaking changes" warned ([sqlite-vec](https://github.com/asg017/sqlite-vec)).

The query pipeline is the training-free composed-retrieval pattern from **CIReVL (ICLR 2024)** ([CIReVL](https://eml-munich.de/publication/CIReVL)) and **MCoT-RE**. MCoT-RE splits a filter caption from a rerank caption and reports up to +8.58% R@1 over prior training-free methods ([MCoT-RE](https://arxiv.org/html/2507.12819v1)). Applied here, the pipeline runs in four steps:

1. Muse Spark turns the reference image plus the requested change into target-attribute JSON and a target caption.
2. Candidates are filtered on the changed attribute.
3. The remaining candidates are scored as α·image-similarity, plus β·text-similarity, plus γ·overlap on the kept attributes.
4. Muse Spark reranks the top 20 with reasons, which also gives you explainability for the demo.

Do all corpus tagging and segmentation offline, so the ~39 s first-token latency only hits the final rerank, and stream that call.

For the front end, **use React with react-konva (MIT)**, which gives drag, resize and PNG export in a few hundred lines. **Avoid tldraw**: it needs a production licence key and watermarks without a paid commercial licence ([tldraw license](https://tldraw.dev/sdk-features/license-key)). Match react-konva's version to your React version, because v19.3.0 requires React ≥19.3 ([react-konva release](https://newreleases.io/project/github/konvajs/react-konva/release/v19.3.0)).

**Deploy the front end on Vercel Hobby and the backend on a Hugging Face Docker Space** (free CPU, with the Meta key stored as a Space secret). Ship the precomputed index inside the image. Modal's $30/month free credits are the fallback if you want scale-to-zero ([Modal pricing](https://modal.com/pricing)). **Avoid Render's free tier.** It has 512 MB of RAM, 0.1 CPU and about a one-minute spin-up, which cannot hold a PyTorch embedder ([Render free tier](https://render.com/articles/platforms-with-a-real-free-tier-for-developers-in-2026.md)). Wake the Space before judging and record a fallback video.

## Conclusion

Two constraints shape this project more than any model capability. First, Meta's India carve-out removes only image generation, so "retrieve, don't generate" is the version of the product that is legally available to an Indian builder, not merely a stylistic choice. Pitch it that way. Second, the domains the brief names first, modern watches and UI screens, are exactly where the licensed web is thinnest. Building small, fully attributed corpora for them (Commons watches, self-captured open-source UI screenshots) is part of the product, not a chore. A provenance table rendered as credits on every card turns licence discipline into a visible feature. Because the engine works from attribute JSON, it should transfer to a fourth domain from a few hundred images, and showing that is a stronger "domain-agnostic" claim than raw corpus size.

Several things remain open and should be checked in the first two days:

- the $150 credit claim and payment setup, since applying it takes about two business days;
- an authenticated `/v1/embeddings` probe;
- whether `meta-models/muse-spark-open` or `meta-models/muse-spark-open-1026` resolves on Baseten;
- the open-weight bonus rules on the gated event page;
- the Unsplash Lite dataset licence;
- a reply from Pexels on ML use.

The Spark-plus-SAM pipeline is not hostage to any of them. The cheapest way to earn an open-weight bonus, if one exists, is a single reasoning step such as the rerank routed through Baseten's Muse Spark Open, with the required "Built with Muse Spark Open" notice in the UI.
